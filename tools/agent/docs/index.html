01 / The click

The process can stop. The agent home does not.

Bench keeps the governed definition, curated memory, skills, specialist homes, mutable work and state, independently written evidence, effect state, authority limits, and executable check. Ask reconstructs the normalized request history; a named checkpoint resumes that same session. Only the live compute and process-local scratch are replaceable.

01 · contract

What did we ask for?

GOAL.md and the admitted definition stay fixed while intelligence tries different solutions.

02 · authority

What may this run do?

The caller selects capabilities and network policy. Exact May grants are bound to reviewed bytes and spent once.

03 · evidence

What actually occurred?

Ask events, sealed records, and Tend lifecycle events survive execution and can be folded, queried, and integrity-checked.

04 · acceptance

What counts as done?

An operator-owned bin/check accepts or rejects the artifact. The model cannot certify its own answer.

Fresh execution.
Same obligation. Replay verifies the recorded history; it does not re-perform an external effect or prove that a source told the truth. That narrower promise is what makes the guarantee inspectable.

The worker may…

  • Read its definition and selected procedures
  • Use caller-provisioned programs
  • Write deliverables beneath work/
  • Keep mutable facts beneath state/
  • Propose exact patches and external effects

The worker cannot grant itself…

  • Network access from Markdown
  • Persistent writes outside confined roots
  • Permission to execute an external effect
  • A passing completion verdict
  • An automatic skill or definition update

02 / One obligation

From “write release notes” to a check-accepted artifact.

Picture a repository worker whose goal is to produce work/release-notes.md. The model is useful inside the loop—but the loop, confinement, events, and acceptance remain separate owners.

  1. 01

    Validate

    Agent validates the home and runs the check before any model call. Already done means zero-model completion.

  2. 02

    Select

    Brief chooses a relevant local procedure deterministically first; its optional model fallback is explicit and replayable.

  3. 03

    Propose

    Ply + Ask frame one action and record the normalized request, output, usage, observation, and outcome.

  4. 04

    Confine

    Cage runs the model-authored command with caller-selected persistent-write roots and network policy.

  5. 05

    Check

    The trusted bin/check runs outside Cage. Exit 0 accepts; exit 1 returns evidence; anything else is broken.

  6. 06

    Seal + resume

    The verdict is sealed into Ask history. A locked checkpoint points to the named session for a later execution.

↯

Publishing is a second boundary. The worker may write a proposal, but agent act executes outside Cage through operator policy, exact May authorization, and a connector. If an effect may have started without a trustworthy receipt, status 125 makes that uncertainty durable and blocks an automatic retry.

✓

Completion is a program’s opinion. The quality of that opinion depends on the operator’s check—but it never depends on the model saying “looks good.”

The refusals are features. Ask has no tools. Brief does not decide. Context does not synthesize. Cage does not infer intent. Tend does not claim exactly-once effects. Keeping those jobs separate prevents invisible authority from accumulating in one runtime.

Who owns what?
OperatorGoal, instructions, check quality, available programs, and deployment boundary
CallerModel policy, writable roots, network choice, procedure path, and execution flags
ModelReasoning and proposed actions inside the admitted task and supplied capability set
CagePersistent-write and network confinement for model-authored commands on supported hosts
ControllerChecks, definition admission, policy, approvals, credentials, connectors, and effect receipts
Ask + TendAppend-only model-request evidence and event-sourced local process lifecycle state

Honest boundary: Cage is host-level write/network confinement, not a VM. It does not provide complete read, secret, identity, syscall, CPU, memory, or PID isolation. The trusted check runs outside Cage, so operators must not make worker-written verifier code authoritative.

05 / Now and next

A strong semantic core. An honest execution boundary.

The architecture is useful now on a Unix host. The production machine boundary is the next layer—not something the current site should pretend has already shipped.

implemented

Unix-host control plane

Folder homes, checked model loops, write/network confinement, exact request-event replay, named checkpoints, evidence queries, reviewed learning, exact approvals, controlled effects, and optional local Tend durability.

development scaffold

Guest-process foothold

A Fedora mkosi/QEMU image and exact guest-process seam can produce a provisional receipt. There is no broker, transport, lock verifier, production isolation proof, or controller authority in that guest today.

proposed

Sealed per-task Linux VM

A replaceable task machine beneath an external controller, with signed capabilities, workload identity, credential and effect proxies, resource limits, egress policy, and authoritative post-exit receipts.
