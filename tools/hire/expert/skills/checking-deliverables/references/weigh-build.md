# Build and evaluate a selected Weigh composition

Use this procedure only when the requested work selects or changes Weigh.
`BENCH_WEIGH=1` permits adding and running it; default-off builds need no Weigh
decision or evaluation files. Preserve existing dependencies during unrelated
revisions. The caller separately selects the selector and any repair model.

Keep the composition small: ordinary rules settle established facts; Weigh
answers a remaining typed question; the existing caller executes an allowed
action and applies its unchanged final check. Weigh does not supply commands,
an action loop or acceptance authority. Reuse the public `select-fix.py` or
semantic-check example from an explicitly selected Bench source when suitable.

Author concrete questions or an action menu and runnable caller wiring, with
model and executable paths selected at invocation. Include the task, actual
candidate, source evidence and check findings. A pass/fail label alone cannot
establish whether the candidate is correct. Retain the native selected value
and distribution; provider confidence is not calibrated correctness.

Runtime adapters honor `BENCH_WEIGH`: applicable rules can work while off, but
an unresolved required judgment stops with broken-check/selection status (2).
Do not skip acceptance checks or silently call another model. Test the actual
adapter with the switch off and on; inspect generated code before executing it
through the existing action boundary.

Keep job-specific evaluation inputs, independent expectations and results
outside `expert/`. Choose their format for the job; Hire requires no manifest
or case schema and its structural verifier does not run these tests. Exercise
the actual authored questions and wiring on correct outputs, defects, and
plausible ambiguous or missing-evidence cases. Test broken inference and an
unsuccessful repair, including leaving a defective candidate unchanged. Every
action still reaches the independent final checker.

Offline fixtures establish process behavior, not model accuracy. A bounded
live comparison uses the same cases, action menu, runner and final check for
ordinary rules and the optional Weigh path. Count selection, repair and final
checking when reporting quality, time, tokens, calls or cost. Keep unknown
measurements unknown and preserve failed trials. If the role is judgment only,
measure false acceptance and rejection against independent labels and inspect
completed worker outputs before claiming an improvement.

Freeze the proposal before evaluation. Labels come from the task and source
facts, not the proposed check or a teacher model's answers. If evaluation
feedback guides an edit, retain fresh cases for the next comparison; broad
claims need representative jobs beyond renamed fixtures. Keep expected answers
out of model inputs. Separate directories alone do not make holdouts private:
Cage limits writes and networking, not host reads.

Report what ran, observed gains and regressions, and any pending live comparison.
Export only reusable source under `expert/`. A valid question, complete test
folder or fast selector is not proof of better completed work.
