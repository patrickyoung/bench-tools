# Simple site team

Use the exported `page-team` definition at the caller's recorded source commit.
The actual subject, content and expected behavior come from the current brief.

Select Frontend and Reviewer. The frontend owns semantic HTML, responsive
layout, accessible controls, functional vector diagrams and modest motion.
Add a creative specialist only when a concrete requirement needs its capability.

The manager admits frontend creation, review of the accepted HTML, and final
frontend copying of the reviewed bytes. Give creation and review sufficient
turns for checks and final submission; reserve six turns for exact final copy.
A rejected result needs a bounded correction with actual accepted inputs, then
another review. The final file must match the passing review's digest.

Supply only the new brief and explicitly selected current inputs. Each worker
gets its own task/context and workspace. Its handoff uses the existing manifest
contract. No previous page, conversation, recording or development directory
is a default input.

Acceptance: one self-contained HTML file, meaningful interaction journeys,
no runtime network requests, no horizontal overflow at 320px, keyboard access,
visible rendering fallback, reduced-motion behavior, and a passing browser and
visual review. Product-specific requirements must also be checked independently.
The delivered artifact is stdout on exit 0; progress and evidence stay separate.
