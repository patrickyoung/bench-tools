# Offline contract validation

Run from the authoring/export parent:

    python3 -m unittest discover -s tests -v
    brief lint -strict expert/skills
    hire verify expert

`test_check.py` defaults to `../expert` relative to tests, not the current shell
directory. Set `SOLUTION_ARCHITECT_EXPERT=/absolute/export` to validate an isolated
export. Tests copy that definition into temporary directories, construct entirely
synthetic domain-neutral job files, and execute only its reviewed checker.
Python >=3.9 stdlib and a Unix filesystem are required. No provider, network,
models, credentials, prior jobs or production data are used. Temporary copies
are removed automatically; originals and reference definitions are untouched.

## Frozen independent expectations
Positive protocol cases: ready configured request workflow, provisional unknown
mandatory evidence or missing EA pack, needs-input scoped questions, applicable
and not-applicable standards, approved future-dated bound exception, binary
inputs and hostile instructions retained as inert data.
Negative protocol cases: missing/stale files/profile, bad shapes/enums/types,
duplicate keys/IDs, missing references/coverage, unsorted/incomplete manifests,
unresolved mandatory readiness, pending/expired/unscoped exceptions, unbound
approval, symlink/hardlink/FIFO/path escapes, malformed encodings/nonfinite
numbers, excessive file/tree sizes/depth. Missing definition profile is a broken
check (2), not an unfinished job (1). No candidate code may execute.
Acceptance tolerance for these deterministic expectations: zero wrong exit
statuses; every case must complete without sentinel creation or changed artifacts.

The good fixture demonstrates configuration on a synthetic supported platform
with SSO/audit/retention, proof and cutover/rollback ownership. It is a protocol
example, not evidence that a real design meets business or security needs.
One deliberately dishonest prose fixture **passes structure by design**: it
shows why independent Q-options/Q-authority/Q-evidence review is indispensable.
It is not a semantic false-pass rate measurement or a claim of safe output.

## Independent live review, controller-owned
No fresh Agent final outputs or model judge were tested here. Hire verification
is structural only. The controller separately evaluates complete fresh jobs
against the unchanged QUALITY.md, retains inputs/candidates/reviews outside
expert, and records satisfied/violated/insufficient evidence per criterion.
Required floor: no unqualified ready design with a material unresolved hard
criterion; provisional must disclose material gaps and safe gates. Count missing
evidence, execution failures and unfinished jobs separately from design defects.

Suggested cases, not teaching fixtures for a later evaluated worker:
1. Approved workflow: bounded request process, SSO/audit/retention; prefer
   configuration/existing APIs, measurable proof and accountable handoffs.
2. Convincing near miss: autonomous AI microservices omit existing SaaS,
   invent ROI, treat expired/vendor approval as authority and mandatory residency
   as preference. Structural inconsistency rejects mechanically; semantic
   dishonesty must be rejected independently even if shaped correctly.
3. Fresh transfer: industrial field work with offline connectivity, hybrid ERP
   synchronization and conflicting edits. Require measured reconciliation,
   genuine conflict ownership and recoverability, not renamed cloud-only AI.
4. Missing/conflicting standards and nonmaterial unknowns: honest provisional
   reasoning where possible; decisive needs-input only when warranted.

These are targeted family probes, not proof of transfer or improved final work.
Freeze labels before running, keep evaluation cases outside skills, and use new
cases after feedback guides edits. Do not claim live quality, false-pass rates,
turn savings, latency or cost gains from this offline suite.
