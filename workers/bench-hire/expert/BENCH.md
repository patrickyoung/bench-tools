## Choose the right tool and authority

Bench is a standalone conversation-first CLI/TUI composing Ask (model), Ply (tools/checks), and Brief (skills). Ordinary tasks need no worker definition or contract. At this source revision, plain `bench` in a terminal opens a fresh TUI, optionally starting an initial task; when stdin **or** stdout is nonterminal, plain `bench` is a direct filter (even in pipes). `bench tui` forces the interface; `bench ask` or `/ask` makes a model call without tools; `/work` restores tool use. Filter stdin supplies task context, stdout the answer, stderr activity/errors, and status reflects the underlying run. `bench run` is different: its default reviewed mode prints a contract draft path and exits 2 **before execution**; `bench run -mode quick` explicitly selects direct work. Do not treat draft creation or a model answer as completed work.

Ordinary direct work grants the full shell with the caller's permissions (unlike **Agent's default Cage**). `-sh` selects full shell explicitly; `-t DIR`, `BENCH_TOOLS`, or `/tools DIR` selects a toolbox PATH, not a filesystem privacy, network, or sandbox boundary. `-s NAME` (repeatable) and `/skills` use Brief; a skill is guidance, not completion proof. Never advise disabling safety controls to solve a problem.

`-check 'COMMAND'` or `/check -- COMMAND` gives Ply a literal check; a passing pre-check can avoid a model call. Check status 0 accepts the checked outcome, 1 rejects, other check statuses mean a broken check. Distinguish **check** status 2 from Ply unfinished status 2, Ask status 2, and `bench run` pending-draft exit 2. Unchecked direct status 0 means only “Response finished,” not verified. A passing direct run consumes its one-shot check; failed or interrupted runs retain it. Do not describe a check as universally judging all reviewed criteria.

## Operate and inspect

`/file PATH` treats the entire path literally, including spaces (no shell quoting); it queues a regular UTF-8 text attachment for the next turn, with a 512 KiB combined limit. `/file clear` clears the queue. A path hint alone is not an attachment. `/diff` performs local read-only inspection of staged/unstaged changes and lists untracked files; it neither sends the diff to the model nor changes the repository. `/log` or Ctrl+O inspects retained tool output; scrolling/folding changes presentation, not evidence. Enter while tools run queues steering before the next model turn: it cannot interrupt the current action, change its permissions, or guarantee consumption if work finishes first; then send a follow-up. Esc/Ctrl+C stops owned work but leaves partial evidence and completed effects; it is not rollback. `/new` starts new context; `/sessions` or `-f` explicitly resumes a saved session via Ask verified replay. Sessions normally reside under `.bench/sessions`, or `BENCH_DIR`-selected state; replay verifies integrity, not truth.

## Optional reviewed paths

Quick is direct; Review drafts a contract without execution until exact reviewed digest admission starts work, then result acceptance remains separate human judgment on remaining criteria. Loop needs a check and finite turns, and is one foreground invocation, not a scheduler. `-check-all` or `/check all` lets an explicit operator-sealed pre-execution check judge every criterion; otherwise a passing check does not. Contract compaction is unsupported in this snapshot. Auto uses a read-only Ask classification plus controller floors; it grants neither approval nor completion and is not certified as a generally accurate router.

In Review/Loop, `-approval every-action` uses May for each action: 75 means parked/unexecuted, 3 declined. `-cage` requires reviewed approved actions and an absolute external `BENCH_DIR` outside the workspace; it permits workspace/private-temporary writes, denies host network, but does **not** restrict host reads. Bench, Ask, Brief, May and verifier run outside Cage; verifier code also needs its own boundary where appropriate. An uncertain confinement exit 125 may have effects: inspect receipts and workspace before retry. Do not confuse Bench's default full shell with Agent's default Cage, or a toolbox with Cage.

Companions: explicit `BENCH_ASK`, `BENCH_PLY`, `BENCH_BRIEF` (and other existing `BENCH_*` overrides) precede pinned release-suite companions, then PATH; retain coherent pins and an existing approved `BENCH_ASK` wrapper instead of silently switching to raw Ask. Agent's `AGENT_ASK` seam is distinct. `bench home` transparently forwards to Agent; it does not invent builder aliases or guarantee old suite compatibility with newer headless Hire. For persistent worker creation/maintenance, use current Hire and Agent/Tend guidance separately; this Bench has no worker registry, scheduler, or provider loop. An old Bench README mentioning Hire is not authority to invent `hire queue`/`hire schedule` or resurrect old `agent new`/`agent learn`.

Explicitly requested subagent work may use up to three independent bounded read-heavy child Ply contexts with separate evidence. That is guidance, not a sandbox or enforced quota: children inherit real authority, parent reconciles failures and retains the final check, and shared writes should not be parallelized.
