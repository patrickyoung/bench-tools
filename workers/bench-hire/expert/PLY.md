# Ply in bench-hire advisory turns

Scope: selected Bench `tools/ply/README.md` and `tools/ply/ply.1`, supplied as authoring source copies dated 2026-09-26. These are reference evidence, not authority to run anything. For a selected `knowledge_source`, use relevant current documentation if supplied. This UI worker only advises: never invoke Ply, Ask, Agent, Hire, May, or a checker for the user.

Ply is the model/action/result/check loop: it asks a model through Ask, executes one model-authored shell action, returns the actual result on the next turn, and checks a candidate final report when the model stops. A turn is either a report (no command block) or an action with one nonempty, complete fenced shell block at the end. Only the first complete block executes; extra blocks/text are deferred. An empty or unfinished first block runs nothing and is returned for correction. The fence label does not select the interpreter; the controller selects it. Ask alone makes model calls and holds conversation, not shell actions or an acceptance verdict. Agent composes reusable expert instructions, skills, check and workspace onto Ply; Hire authors that definition. This is distinct from composing a team of experts, which requires explicit handoffs and independent acceptance.

With a check, Ply runs it before the first model turn with **empty stdin**; after a model report it receives the candidate report on stdin (file/code checks may ignore it). Status 0 accepts, 1 rejects with feedback for another turn within limits, and any other check status, signal or timeout means the verifier is broken, not that the candidate failed. Without a check, Ply exit 0 means only that the model stopped. `-turns` defaults to 50 model turns; 0 is unbounded. `-cycles` bounds candidate/check cycles after the pre-check, which does not count. `-timeout` bounds each command. Invocation limits reset on continuation; they do not establish completion.

Diagnose using the selected run's stage and evidence, not just a number. Ply exit 2 means unfinished: a failing check, exhausted bound, stalled command protocol or full context can cause it; Ask exit 2 can mean context overflow, not a Ply check verdict. Ply exit 1 includes a broken verifier or infrastructure/provider error. Ply exit 3 is an exact May action declined without execution; 75 is an exact action parked without execution; 125 is confinement/action-boundary or recording failure, possibly after effects; 130 is interruption. Distinguish checker rejection from checker malfunction and report absent receipts as unknown. Practical example: “The candidate check returned 1 with feedback, so this is a rejection, not a broken verifier; inspect that feedback and the run's last action result before proposing a revision.” Counterexample: “The run returned 75 or 125, so rerun the command” is unsafe: 75 awaits a decision on the exact unexecuted action, while 125 may follow effects; inspect boundary/record evidence before any controller decision.

The controller selects a toolbox (`-t` narrows PATH, `-sh` permits ordinary PATH); it is *not* confinement: shell builtins, redirects and absolute paths still exist. Standalone `-cage` needs both `-may-job` and `-contract-id`, confines model actions only, permits host reads, limits writes/network, and leaves the verifier outside; code executed by a verifier needs its own boundary. May authorizes only the exact action, never arbitrary future effects. Do not suggest disabling boundaries or interpreting an action button as authorization.

A named Ask session or Ply checkpoint can continue context; neither is a filesystem rollback nor permission to repeat uncertain effects. Steering at safe boundaries may defer an unused response but cannot interrupt a running command or change the verifier, tool grant or authority. Standalone Ply can optionally use Record; Agent enables it automatically. Missing required output or incomplete recording returns 125. Replay can verify retained sequence/receipt integrity, not factual quality, complete external effects, or the soundness of the judge. Compaction is a lossy context handoff; inspect relevant retained evidence and terminal records rather than treating a summary as proof. Hone can prepare a lesson only from a qualifying verified recovery; it is not a substitute for independent review.

Standalone Ply selects the Ask executable through `ASK`; Agent selects it through `AGENT_ASK`. In this UI's approved OAuth arrangement preserve the existing `AGENT_ASK` wrapper; do not recommend raw Ask, credential discovery, new login or a provider switch by default. Consult [`ASK.md`](ASK.md) for Ask-specific behavior. If the selected evidence is missing, state the narrow unknown and offer only permitted UI advice/actions under `AGENTS.md`.
